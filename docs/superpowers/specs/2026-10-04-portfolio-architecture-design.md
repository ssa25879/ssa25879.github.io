# 포트폴리오 기능 분리 설계

## 목적과 범위

사용자 요청: 순수 HTML을 유지하면서 하나의 파일에서 모든 기능을 작업하지 않도록 분리한다.

기존 화면, 한국어 콘텐츠, 프로젝트 5개, 외부 미디어 URL 및 반응형 스타일을 유지한다. 프레임워크, 패키지 설치, 빌드 도구 및 HTML 동적 로딩을 도입하지 않는다. 원격 저장소 반영과 배포는 이번 구조 변경 범위에 포함하지 않는다.

## 확인한 현재 상태

- 기준 브랜치: main, 커밋: 85969cb02da408318b9e85a664d7edae157ee2d4.
- 실제 파일은 README.md와 index.html 두 개다.
- index.html에 CSS, 콘텐츠, 인라인 이벤트 및 JavaScript가 함께 있다.
- 테마 변경, 모바일 메뉴, 프로젝트 상세 전환, 카드 키보드 입력 및 History API 처리가 존재한다.
- 기존 코드는 상세 URL의 새로고침 시 복원과 테마 저장을 구현하지 않는다. 구조 분리 과정에서 별도 기능을 추가하지 않는다.

## 파일 구조와 책임

```text
index.html
assets/
  css/
    tokens.css
    base.css
    layout.css
    sections.css
    projects.css
    responsive.css
  js/
    theme.js
    navigation.js
    projects.js
    app.js
README.md
```

- index.html: 의미 있는 HTML 콘텐츠와 외부 CSS/JS 참조를 담당한다. 기존 메인·상세 콘텐츠는 이곳에 유지하며 실행 코드와 이벤트 속성을 제거한다.
- tokens.css: 기본 색상·간격·반경 변수와 다크 테마 변수.
- base.css: 리셋, 기본 글꼴·본문·제목·링크 및 포커스 스타일.
- layout.css: 상단 내비게이션, 모바일 메뉴, 공통 섹션 레이아웃.
- sections.css: 소개, 히어로, 기술, 자격증, 연락처 및 해당 버튼 스타일.
- projects.css: 프로젝트 카드와 상세 화면 스타일.
- responsive.css: 기존 미디어 쿼리를 원래 순서대로 보존.
- theme.js: 테마 버튼 연결과 다크 테마 전환.
- navigation.js: 모바일 메뉴 토글과 내비게이션 연결. 메인 화면 복귀는 projects.js가 제공하는 함수에 의존한다.
- projects.js: 메인·상세 표시, 카드 클릭·Enter/Space 처리, 목록 복귀 및 popstate 처리.
- app.js: 각 기능 초기화만 담당한다.
- README.md: 파일 역할, 로컬 확인 방법, 콘텐츠와 프로젝트 추가 방법, 배포 전 확인 항목.

CSS는 위 목록 순서로 로드하여 기존 선언 우선순위를 유지한다. 인라인 스타일은 관련 클래스에 옮기고, 기존 값은 유지한다. 과도한 세분화를 피하기 위해 개별 소개 섹션마다 별도 파일을 만들지는 않는다.

## JavaScript 연결과 실행

빌드와 로컬 HTTP 서버를 필수로 만들지 않기 위해 외부 일반 스크립트를 defer로 순서대로 로드한다. 각 기능 파일은 즉시 실행 함수 내부로 구현을 감추고, 하나의 Portfolio 네임스페이스에 초기화 함수와 필요한 메인 화면 복귀 함수만 공개한다. HTML에 onclick/onkeydown을 남기거나 기존 함수들을 개별 전역 함수로 공개하지 않는다.

프로젝트 카드는 data-project-id로 기존 detail-N을 참조한다. 내비게이션과 복귀 버튼은 data 속성으로 동작을 표시한다. app.js가 theme, projects, navigation 순으로 초기화하여 기능 간 의존성을 명확하게 한다. 기능별 이벤트는 해당 기능 파일에서만 등록한다.

프로젝트 상세 표시는 해당 ID가 존재하는지 확인한 뒤 실행한다. 잘못된 참조는 현재 화면을 유지하며 예외를 발생시키지 않는다. 페이지 이동, 해시 생성, history.back 및 popstate에 따른 화면 복귀 의미를 기존 구현과 동일하게 유지한다.

## 검증 기준

1. HTML에 실행용 인라인 script/style 및 onclick/onkeydown이 남지 않는다.
2. 모든 로컬 CSS/JS 경로가 존재하고 JavaScript 구문 검사를 통과한다.
3. 기존 텍스트, 링크, 이미지·iframe 주소, 프로젝트 ID와 연결 관계가 유지된다.
4. 브라우저에서 테마 토글, 모바일 메뉴, 프로젝트 5개 열기, Enter/Space, 목록 복귀, 뒤로/앞으로가기를 확인한다.
5. 데스크톱과 모바일 너비에서 주요 화면과 CSS 우선순위를 비교한다.
6. 외부 미디어 접근 실패는 구조 변경과 구분한다. 실행 환경상 확인할 수 없는 항목은 미검증으로 보고한다.

## 복구와 후속 절차

원본 사이트는 기준 커밋에 보존되어 있다. 사용자 변경을 덮어쓰거나 커밋하지 않는다. 작업 로그는 사용자 요청에 따라 작성하지 않는다.

이 설계서 검토 후 구현 계획을 작성한다. 계획 검토와 실행 방식 선택이 끝나면 로컬에서 기능을 분리하고 검증한다.
